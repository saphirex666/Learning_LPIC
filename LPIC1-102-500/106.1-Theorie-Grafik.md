🎓 LPIC-Praxisfall: Linux als Kiosk-System mit X11 & systemd
🎯 Ziel des Szenarios
Ein Linux-System (Raspberry Pi / Debian) soll:
automatisch booten
grafische Oberfläche starten
Bildschirmauflösung korrekt setzen
eine Anwendung (Chromium) im Kiosk-Modus ausführen
stabil im Dauerbetrieb laufen
Fehler nachvollziehbar loggen
➡ Das ist klassische Linux-Systemintegration, genau das, was Admins real tun.
🧠 Architektur: Was passiert technisch?
1. Boot-Prozess (LPIC-1 & 2)
Reihenfolge:
Firmware / Bootloader
Kernel
init → systemd
systemd startet:
Netzwerk
Display Manager (LightDM)
LightDM startet Xorg
Xorg startet Desktop-Session (LXDE/Openbox)
Autostart-Skripte des Users laufen
👉 Wichtiges LPIC-Wissen:
Wer startet was?
Wo kann ich Prozesse einklinken?
systemd vs User-Session
2. Display-Stack: Kernel → DRM → Xorg → Anwendungen
Kernel
Treiber: vc4 (DRM/KMS)
Erkennt Monitor per EDID
Wählt bevorzugte Auflösung (oft 4K)
Xorg
Nutzt DRM-Gerät
Erstellt Display :0
Verwaltet Auflösung, Position, Rotation
xrandr
Werkzeug, um Xorg zur Laufzeit umzuschalten
Ändert nicht persistent, nur aktuelle Session
👉 LPIC-relevant:
Unterschied Kernel-Mode-Setting vs User-Space
Runtime vs Konfiguration
Tools: xrandr, xset, xdpyinfo
3. Warum Auflösung nicht reboot-sicher ist
Weil:
EDID vom Monitor sagt: „Ich kann 4K“
Kernel/Xorg nehmen beim Start den besten Modus
Dein manuelles xrandr kam erst danach
➡ Nach Reboot ist alles wieder neu initialisiert.
LPIC-Prinzip:
Alles, was nur im RAM passiert, ist nach Reboot weg.
Darum:
entweder Boot-Konfig (/boot/firmware/config.txt)
oder Autostart-Skripte
4. Benutzerkontext & DISPLAY (extrem LPIC-wichtig)
Warum läuft GUI nicht als root?
X11 gehört dem eingeloggten User:
Display: :0
Cookie: ~/.Xauthority
Wenn root etwas anzeigen will:
export DISPLAY=:0
export XAUTHORITY=/home/sadmin/.Xauthority
Sonst:
❌ Cannot open display
LPIC-Knowledge:
Trennung Kernel / User / Session
Sicherheitsmodell von X11
Warum GUI nie direkt als root laufen sollte
5. Desktop Autostart vs systemd (LPIC-2 & 3)
Variante A – User Autostart (LXDE)
Pfad:
~/.config/lxsession/LXDE-pi/autostart
Startet:
nachdem Desktop läuft
im User-Kontext
Gut für:
Kiosk
Benutzerprogramme
Variante B – systemd Service
Startet:
ohne Desktop
systemweit
mit Abhängigkeiten (network, display, etc.)
Beispiel:
After=graphical.target network-online.target
LPIC-Themen:
systemd Targets
Dependencies
Restart Policies
Watchdogs
6. Kiosk-Browser = Prozessmanagement
Wir starten Chromium mit Flags:
--kiosk → Vollbild ohne UI
--disable-gpu → stabil auf Embedded
--use-gl=swiftshader → Software-Rendering
Das ist klassisch:
Applikation fest binden
keine Benutzerinteraktion
kontrollierter Start
LPIC-Bezug:

Neustartstrategien
